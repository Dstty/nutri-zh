# nutrimatic-zh · 汉字正则查找

在 **120 万字词**语料中按正则模式检索中文字词。受 [Nutrimatic](https://nutrimatic.org/) 启发，针对中文重做了模式维度。

```
.国              → 中国  美国  英国  法国  德国  韩国 …
[东西南北]风      → 东风  西风  北风  南风  西北风  东南风 …
.{2}             → 只出二字词
中.              → 中以  中心  中国  中央 …
..*人            → 中国人  机器人  主持人  负责人 …
```

## 快速开始

```bash
python serve.py                 # 启动本地服务并自动打开浏览器
```

需要本地服务的原因：直接以 `file://` 打开 `index.html` 时，浏览器会拦截本地
`fetch` 读取数据（同源策略）。

数据已随仓库提供，克隆后即可运行。若想从原始数据集重建索引，见下方「重建索引」。

> **在线预览**：仓库设置里开启 Pages（Settings → Pages → Source: `main` / `/ (root)`）
> 后，即可通过 `https://dstty.github.io/nutri-zh/` 直接使用，无需本地服务。

## 语法

| 写法 | 含义 |
| --- | --- |
| `.` | 任意一个字符 |
| `[东西南北]` | 字符类，匹配其中任一字符 |
| `[^东]` | 排除类 |
| `[一-五]` | 字符范围 |
| `X*` `X+` `X?` | 零或多次 / 一次或多次 / 零或一次 |
| `X{n}` `X{n,}` `X{n,m}` | 精确次数 / 至少 n 次 / n 到 m 次 |
| `(中\|国)家` | 分组与或 |
| `\x` | 转义元字符 |

默认**在词内任意位置**查找，不要求整词匹配——所以 `[东西南北]风` 既能出
`东风`，也能出 `西北风`。勾选「整词匹配」则要求完全吻合。

**全角自动归一**：中文输入法下打出的 `．［］（）＊＋？｜｛｝＾` 会自动当作
半角元字符处理，不必切换输入法。

**词长限定**：`{2}` 只出二字词，`{2,4}` 限定二到四字，`G` 前缀则连同单字一起列。

## 结果

- 按词长分组展示，同长度内按语料频次降序，常见词自然靠前
- 点击任意结果复制
- 长查询流式推进：边扫边出，状态栏显示已扫描比例

## 数据

| 项 | 规模 |
| --- | --- |
| 词条 | 1,208,295 |
| 单字 | 9,574 |
| 语料来源 | [rime-ice](https://github.com/iDvel/rime-ice) 简体词库 + [rime-essay](https://github.com/rime/rime-essay) |
| 单字字段 | 笔画名序列（26 种笔形）、常用度权重 |

`web/data/` 下三个文件：`chars.txt.gz`（单字）、`words.bin.gz`（词流 + 块级倒排）、
`meta.json`（元信息）。

词流按**词长升序、同长度按频次降序**排列，因此高频词集中在前面，扫描可以
提前出结果；块级首字倒排则让带起始字符约束的模式跳过绝大多数块。

## 重建索引

数据已随仓库提供，一般无需重建。若要自己重跑：

```bash
node tools/build_index.mjs      # 产出 web/data/*
node tools/test.mjs             # 需先启动 serve.py
node tools/test_ui.mjs          # UI 冒烟(无需服务)
```

`build_index.mjs` 需要两类输入：

- **汉字数据集**：`hz_full.jsonl` / `hz_common.jsonl`，默认从仓库上一级目录读取，
  可用 `HZ_SRC` 覆盖
- **词表**：若 `data/wordlist.tsv` 不存在，会尝试从 `$HZ_SRC/data/` 下的
  `essay.txt`、`rime_ice_base.dict.yaml`、`rime_ice_ext.dict.yaml` 自动构建

```bash
HZ_SRC=/path/to/dataset node tools/build_index.mjs
```

## 实现

匹配交给引擎内置 `RegExp`（V8 的实现成熟且快），本项目的价值在于围绕它解决
中文检索的三个具体问题：

1. **块级倒排预筛**。词流每 1024 条一块，记录该块所有词的首字符。模式以明确
   字符开头时可跳过整块，把一个 100 万词的扫描压到毫秒级。
2. **流式扫描**。按帧限时推进（约 11ms/帧），边扫边渲染，长查询不冻结界面。
3. **全角归一与可读报错**。中文输入习惯与英文正则语法的摩擦在本层抹平。

测试以**引擎原生 RegExp 为基准**自动比对，而不是手写期望值——避免把「我以为的
语义」当成「正确的语义」。

```
匹配层 vs 原生 RegExp   24 例一致
搜索数量 vs 原生全表    4 组一致
全量 100 万词扫描      165–221ms
```

## 已知边界

- 匹配单位是**词**，不支持跨词边界的连续匹配（Nutrimatic 的 `A.C` 能命中
  `a cup` 那种）。
- 词表含网络语料词，低频结果里可能出现非规范组合；靠前的词是可靠的。
- 单字笔画名为 26 种笔形细分（横折钩、竖弯钩…），其中约四分之一生僻字由
  运笔几何反推，折笔只给到「折」这一粒度。
